### 계층별 기술 선택

| 계층 | 기술 | 선정 사유 |
|---|---|---|
| 프레젠테이션 | Streamlit | 파이썬 단일 파일로 채팅 UI 구현, 별도 프론트엔드 불필요 |
| 오케스트레이션 | LangChain (LCEL) | 벤더 추상화로 모델 교체 비용 최소화 |
| 문서 처리 | PyMuPDF | 페이지 메타데이터 제공 → 출처 표기에 필수 |
| 청킹 | RecursiveCharacterTextSplitter | 문단 경계를 우선 보존하며 크기 조정 |
| 임베딩 | `models/gemini-embedding-001` | 무료 티어, LLM과 키 단일화 |
| 벡터 저장·검색 | FAISS (in-memory) | 별도 인프라 불필요, 파일럿 규모에 충분 |
| 생성 | `gemini-3.6-flash` | 무료 티어, 긴 컨텍스트 처리 |

### 핵심

일반적인 RAG는 검색 → 이후 무조건 LLM 호출 구조.
본 설계는 그 사이에 판정하는 부분을 배치했습니다.

```
검색 결과
   ↓
최고 유사도 거리 > 0.7 ?
   ├─ 예   → 정형 거절 응답 (LLM 호출 없음, API 비용 0)
   └─ 아니오 → LLM 호출
```

설계 의도

> 근거 부족 여부를 LLM의 판단에 위임하지 않고, 검색 단계에서 정량 지표(코사인 거리)로 선판정하여 환각 발생 경로 자체를 차단합니다.

## 3. 프롬프트 엔지니어링

쓴 기법 4가지

역할 지정
학내 자료 기반 AI 학습 도우미라고 역할을 지정.
AI가 일반 상식으로 빠지지 않고 자료 안에서만 답하게 하려는 목적.
학부생이 이해할 수준으로도 함께 넣어서 

형식 지정 — 답변 형식을 두 가지 지정.
근거가 있으면 [문서명 p.12] 형태로 출처를 붙이고
없으면 "제공된 자료에서 해당 내용을 찾을 수 없습니다"라고만 답하게 하여
답변의 근거가 될 자료가 없을 때 "모른다"고 답하도록 강제하는 별도의 가드레일 설계를 추가했습니다.

Few-shot — 예시 답변 2개
하나는 정상 답변, 하나는 거절으로 답변 시 해당 형식으로 답변할 수 있도록 했습니다. 


마지막으로 지시와 데이터 분리(자료에 포함된 문장을 지시로 오해 방지) 및 답변 생성 시작점을 알려주기 위해 [역할] [규칙] [자료] [질문] [답변]으로 구역을 나눴습니다.

안쓴 기법           
Chain of Thought | 검색된 자료가 이미 답의 근거가 되므로 추론이 필요없어보임.
멀티 페르 소나    | 자료에서 답 찾기는 정답이 하나라 미사용.
이어쓰기         | 정확성이 최우선이므로 llm이 새로 생성하면 곤란하여 미사용.
Q&A              | few-shot과 중복될 것 같아 미사용

## 4. 프레임워크 선택

### LangChain (코드 기반) 채택

#선정 사유

본 프로토타입의 핵심 요구사항인 "유사도 임계값 기반 LLM 호출 차단"은
검색 결과의 거리 값을 직접 읽어 분기해야 합니다.

노코드 플랫폼은 대부분 검색과 생성이 하나의 노드로 추상화되어 있어,
그 사이에 판정을 삽입하기 어렵습니다.

따라서 세부 제어가 가능한 코드 기반 LangChain을 채택했습니다.

### 구현 범위

- 문서 로딩: `PyMuPDFLoader`
- 청킹: `RecursiveCharacterTextSplitter`
- 임베딩·벡터저장: `GoogleGenerativeAIEmbeddings` + `FAISS`
- 프롬프트: `ChatPromptTemplate`
- 체인 조립: LCEL (`prompt | llm | parser`)
